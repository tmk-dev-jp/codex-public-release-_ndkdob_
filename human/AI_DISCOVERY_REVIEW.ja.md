# AIエージェントによる新規発見・研究立案：文献調査と実装

調査日：2026年10月22日。19件の異なる論文・研究系列を調査した。Nature、Science、Nature Machine Intelligence、Advanced Materials、ACL・NAACL・ICLR等の査読論文と、直近のプレプリントを含む。同一研究のプレプリント・出版版やAI Scientistの系列を別々の独立証拠として数えていない。数値としてのIFは確認しておらず、掲載誌の知名度を研究の正しさや進歩性の証拠には使わない。

調査範囲は公式の概要・書誌情報・研究紹介である。全文・補足資料・データ・実装の再現検証は行っていない。以下の成果は原則として著者による報告であり、ここで独立再現した結果ではない。

## 2. 単なる後追いを避ける研究の組み立て方

研究の出発点は「既存論文の方法を別データに試す」ではなく、未解決の問いとする。矛盾する観察、既存手法が破綻する条件、説明されていない現象、現在達成できない能力などから候補を作る。そのうえで、最も近い研究を比較し、何が既知で何が推論なのかを明示する。

新規性と進歩性は分けて評価する。未報告らしいというだけでは有用な進歩とは限らず、単なる得点向上では新しい説明を得たことにならない。主張する進歩に応じて、たとえば次を事前に決める。

- **現象の発見**：既存の説明が予測しない現象を、交絡を排した条件で確認する。
- **機序・説明の前進**：候補の説明と最も強い代替説明が異なる結果を予測する介入を設ける。
- **方法・能力の前進**：同じデータ・計算資源・評価条件で、従来できなかった能力や意味のある改善を示す。
- **境界条件や否定的知見**：一般に成り立つと考えられた主張の限界を、再現可能な反例や条件付きの結果として示す。

再現研究や実装確認は重要だが、それらの完了を発見に読み替えない。逆に、期待と違う結果や否定的結果も、重要な問いを解決するなら前進になり得る。ここでいう進歩性は科学上の貢献であり、特許法上の進歩性の判定ではない。

## 3. エージェントの使い分け

| 役割 | 入力・作業 | 残す成果物と判定 |
| --- | --- | --- |
| 文献調査 | 研究の問いと承認済みの検索範囲から、近接研究・反証・未解決点を確認 | 出典、確認した事実、未確認点。検索で見つからないことを世界初の根拠にしない。 |
| 仮説・計画 | 事実から推論を分離し、意味のある進歩と識別可能な予測を設定 | 一つの中核仮説、代替説明、比較条件、主指標、反証条件、必要な規模。 |
| 独立監査 | 新しいコンテキストで、計画と出典が主張を支えるか確認 | 最も強い反論と不足証拠。多数決や役割数を確信度に変換しない。 |
| 実装 | 固定された比較と不変条件に従ってコード化 | 対照条件を保った実装と検証。失敗時に問いや判定基準を変更しない。 |
| 結果評価 | 実際の出力と固定済みの基準を照合 | 支持・棄却・判断不能、および未検証の範囲。実測と解釈を混同しない。 |

この使い分けは文献から導いた設計判断であり、役割を増やすほど発見能力が向上するという実証結果ではない。既存の一件単位の計画・監査・実装経路を再利用する。

## 4. 実装方針と検証

具体的な契約、互換性、変更箇所、合格条件は[実装計画](../maintenance/AI_DISCOVERY_IMPLEMENTATION_PLAN.md)に記録した。[実装結果](../maintenance/AI_DISCOVERY_IMPLEMENTATION_RESULT.md)には、変更箇所とテストの証拠を記載している。

実装した内容は次のとおり。

- 新しく作る実験に`novelty_contract_version: "1.0"`を自動付与する。
- 新規性記録の`contribution`に、出典で確認した観察、推論、貢献の種類、実質的な前進、代替説明、両者の予測、識別実験、進歩の判定条件を要求する。
- 出典比較に存在しない参照、不足項目、未対応バージョン、同一の予測を拒否する。通常経路、直接の計画承認、エージェントによる新規性判断に適用する。
- 貢献の記録を既存の監査入力・意思決定入力に結び付ける。監査後に内容や契約バージョンを変更した場合は、以前の受理記録を使って継続できない。
- 旧実験・旧記録を自動改変せず、互換性を残す。旧形式を新契約で確認済みとは扱わない。

通常の開始手順で新規実験を作れば契約は有効になる。`$audit-novelty`で`research/novelty/NOVELTY_CHECKS.jsonl`へ記録し、`$plan-experiment`では既存の`Rationale`、`Novelty check`、`Alternative explanation`、`Minimum discriminating evidence`、判定・反証条件へ反映する。[契約の詳細](../automation/SCIENTIFIC_CONTRIBUTION.md)に項目と対応表がある。準備済みの旧実験へバージョンを手動追加・削除して移行する手順ではない。

回帰テストは648件が通過し、既存のサンドボックス依存2件は除外した。250語の上限内に収まる181語の合成応答を、実際の準備・委任記録・ワーカー紐付け・受理APIに通した。出典不足等の拒否時には状態や履歴が変わらないことも検証した。この合成例は実在の研究成果ではない。

監査への質問文を最終調整した後の関連テスト230件も通過した。リポジトリ検証は警告ゼロで、更新した4スキルの形式と文字数、対象コードのlint、差分の空白を確認した。研究状態・目標・キュー・アイデア台帳・新規性記録の5ファイルは変更前と同じハッシュを保っている。

追加の独立コードレビューは、選択した監査ロールが実験計画バンドル以外を閲覧できず、実施されなかった。[応答を原文保存](../maintenance/AI_DISCOVERY_REVIEW_STATUS.md)し、別の監査担当への置き換えや監査済み扱いはしていない。ここで報告する検証は実装テストと統合確認である。

構造検証で確かめられるのは、必要な記録が揃い、参照や計画との対応が保たれていることまでである。世界初であること、引用が主張を十分に支えること、重要な発見が増えることは、この保守実装のテストだけでは証明できない。科学的な妥当性は既存の独立監査と、その後の適切な比較実験で判断する。

## 5. この改良自体を研究として検証する場合

候補仮説は「出典から進歩基準と対立予測までを明示すると、単なる新規性の自己採点より、実行後に根拠が残る実質的な貢献の割合が高まる」である。これは未検証であり、この保守作業で支持された主張ではない。

比較するなら、同じモデル・文献範囲・計算予算・研究課題を用い、従来の計画手順と改良手順を比較する。課題ごとの科学的必要条件を生成前に固定し、失敗も含めた全件を母数に、条件を満たす検証済み貢献の割合を主指標とする。新規性の確認は出典を遡って行い、文章の長さ、査読風の評価点、実行件数を代用しない。

主要な代替説明は、単に記入量や計算量が増えたための改善である。予算と出力条件を揃えた比較が必要になる。成果が文章上の高評価だけに留まる、実験の必要条件を満たさない、既知研究の再現で説明できる場合は、発見能力が向上したとは結論しない。実行可能な課題群と検証資源が未設定のため、この検証研究は開始していない。
