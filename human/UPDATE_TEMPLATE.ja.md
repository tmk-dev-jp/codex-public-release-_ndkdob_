# 既存プロジェクトのテンプレート更新

このスクリプトは、公開 GitHub リポジトリの指定タグ間の差分を取得し、既存の研究ディレクトリへまとめて適用します。テンプレートを事前に clone する必要はありません。依存関係のインストール、コミットやタグの作成は行いません。既存プロジェクトとテンプレートの Git 履歴が異なっていても利用できます。

`--github` には公開リポジトリを `OWNER/REPO` 形式で、`--from-tag` には導入済みのタグ、`--to-tag` には更新先のタグを指定します。Git と HTTPS 接続が必要です。ブランチや HEAD は受け付けず、指定したタグだけを一時的な bare リポジトリへ取得します。注釈付きタグと軽量タグに対応します。作業ツリーの作成、取得したコードの実行、サブモジュールの取得はしません。認証用の対話入力は無効にし、取得時は Git のシステム・グローバル設定を読みません。ネットワーク処理は120秒でタイムアウトし、自動再試行はしません。一時リポジトリは終了時に削除します。

両タグは取得後にコミットハッシュへ固定し、結果に表示します。導入済みのタグが不明な場合は推測せず、まず導入元を確認してください。リモートでタグが付け替えられる可能性があるため、プレビューと適用で表示されるハッシュが同じか確認してください。

```bash
python scripts/update_template.py \
  --root /path/to/project \
  --github OWNER/REPO \
  --from-tag template-v1 --to-tag template-v2 \
  --plan /tmp/template-update-plan.json
```

既定はプレビューです。標準出力には件数と両コミットを含む `OK ...` の一行だけを表示します。`--plan` は任意で、リポジトリ・タグ・解決したコミット・変更パスと追加・変更・削除の区別を JSON に保存します。既存の計画ファイルは上書きしません。出力先は研究ディレクトリの外に指定してください。

JSON の変更一覧を確認したら、同じ版指定に `--apply` を追加して適用します。プレビューで使った `--plan` は省略するか、新しい出力先を指定します。`--path scripts/example.py` を繰り返すことで、対象を許可範囲内の個別ファイルへ絞れます。

従来のローカルモードも利用できます。`--github OWNER/REPO` の代わりに `--template /path/to/local-template` を指定し、`--from-ref` と `--to-ref` でタグまたはコミットを指定します。このモードではネットワークアクセスせず、コミット済みの内容だけを読みます。`--github` と `--template` は同時に指定できません。

更新対象は `scripts/`、`schemas/`、`tests/unit/`、`.agents/skills/`、`src/dl_research/`、`human/`、`configs/templates/`、`experiments/templates/` と、ルートの `AGENTS.md`、`README.md`、`TREE.txt`、`Makefile`、`pyproject.toml`、`.gitignore` です。研究状態、実験実体、データ、成果物、参照資料、論文グラフ、保守記録、`.codex`、実環境の設定は対象外です。対象内でも `.git`、`.venv`、`venv`、`node_modules`、`__pycache__`、`.env` と `.env.*` は除外します。シンボリックリンクと Git サブモジュールは扱いません。

対象にローカル変更、ステージ済み変更、未追跡・無視ファイルとの衝突が一つでもあれば、全ファイルの適用を中止します。自動マージや強制上書きはありません。更新先の内容・モードと一致する通常ファイルは、追跡状態にかかわらず変更しません。このため同じ更新の再実行は変更なしで完了します。追加ファイルは適用後も未追跡なので、通常のレビュー・コミットを済ませてください。ユーザーのインデックスや Git 履歴は変更しません。Git の改行変換などで導入元のバイト列と違う場合も、保守的に衝突として止まります。

`GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE` などの `GIT_*` 環境変数が設定されていれば拒否します（表示用の `GIT_PAGER` と `GIT_TERMINAL_PROMPT` は許可）。設定を解除して通常のリポジトリ指定で実行してください。更新中は別プロセスによる対象ファイルの編集や Git 操作を止めてください。

適用前に一時ディレクトリの `template-update-backup-*` に元ファイル、モード、変更一覧と対象ルートを保存し、成功時の一行に場所を表示します。通常の書き込み失敗では元ファイルへ戻します。各ファイルの置換はアトミックですが、更新全体はアトミックではありません。強制終了・電源断では一部適用が残り得ます。その場合は一時ディレクトリの該当 `plan.json` で対象ルートを照合し、`files/` の元ファイルを元のパスへ戻し、一覧で `add` のファイルを削除します。復旧時はバックアップの実行モードも戻してください。自動再試行はありません。バックアップは動作確認後に削除できます。一時ディレクトリの清掃前に必要なバックアップを保管してください。

適用後は差分とテストを確認してください。`pyproject.toml` に依存関係の変更がある場合は互換性を確認し、分離した環境で検証してから実環境へ反映してください。更新スクリプト自体は既存環境へ依存関係を追加・削除しません。
