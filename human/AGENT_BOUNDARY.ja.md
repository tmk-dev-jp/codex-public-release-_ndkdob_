# エージェントの参照境界を手動で設定する

## 何を設定するか

`scripts/set_agent_boundary.py`は、このプロジェクトのCodexに対して、読める場所・書ける場所を指定するスクリプトです。`SCOPE.json`の作業指示とは別に、Codexのファイルシステム制限を使います。

**人間がターミナルから実行するためのものです。スキル、フック、自律研究ループから自動実行しません。** 設定案の表示だけでは何も変更しません。

| 指定 | 意味 |
|---|---|
| `--read PATH` | そのファイル、またはディレクトリ以下を読取り専用にする |
| `--write PATH` | そのディレクトリ以下の読取り・書込みを許可する |
| `--deny PATH` | 許可範囲内でも、そのファイル・ディレクトリを読取り拒否にする |
| 指定しない場所 | 原則として読取り拒否 |
| 実行に必要な例外 | Codex標準の最小実行環境と、指定したCodex実行ファイルは読取り可能 |

`--write`は読取りも含むため、同じ場所に`--read`を重ねる必要はありません。書込みを許可したプロジェクトの`.git/`、`.codex/`、`.agents/`は読取り専用に保ちます。ネットワークは無効にし、コマンドの権限昇格も要求できない設定にします。

## 実行環境

Python 3.11以上と、名前付きのファイル権限設定に対応したCodex CLIが必要です。Linux/WSLでの境界検査はローカルのCodex 0.154.0-alpha.6.2で確認しています。

以下はリポジトリ直下で実行します。相対パスは`--root`で指定したプロジェクト、またはこのスクリプトを置いたリポジトリを基準に解釈します。`--read`などは複数回指定できます。存在しないパス、ワイルドカード、シンボリックリンク経由の指定は拒否します。

Windowsのターミナルでは`python3`を`py -3.11`などへ読み替えます。WindowsとWSLでは絶対パスが異なるため、**Codexを動かす側のPythonで生成してください**。WSL用に生成した設定をWindowsネイティブ側へそのまま流用しないでください。

## 1. 設定案を見る

リポジトリ内を読み書きできる通常作業用の例です。

```bash
python3 scripts/set_agent_boundary.py plan --write .
```

`OK agent-boundary`に続くJSONで、適用先と許可パスを確認します。この時点では設定ファイルを変更しません。

論文知識グラフだけを編集する例です。

```bash
python3 scripts/set_agent_boundary.py plan --write paper_knowledge
```

追加資料が必要な場合は、その実在パスを`--read`で指定します。Codexが見つからない場合は`--codex /path/to/codex`で実行ファイルを指定します。実験で必要なデータや仮想環境も、許可範囲外なら個別の指定が必要です。

## 2. 手動で適用する

確認した指定をそのまま`apply`へ渡します。進行中の作業を終えてから実行してください。

```bash
python3 scripts/set_agent_boundary.py apply --write .
```

適用先は`.codex/config.toml`です。元の内容を`.codex/agent-boundary-backup.json`に保存し、既存のフック・エージェント設定を維持します。バックアップはGit管理から除外しています。

既存設定に`default_permissions`、`approval_policy`、`sandbox_mode`がある場合は、競合する設定を上書きせずエラーにします。別の権限設定と併用する前に内容を整理してください。同じ指定の再適用は変更を起こしません。

## 3. 新しいタスクで使う

CLIではプロジェクトを信頼したうえで、新しいセッションを開始します。

```bash
codex --strict-config -C .
```

アプリでもプロジェクトを信頼し、新しいタスクで`manual-agent-boundary`が選ばれていることを権限表示で確認します。既存セッション、UIで上書きされた権限、管理者側の設定には自動反映されません。名前付き設定が利用できないアプリ版ではCLIを使ってください。

`apply`の成功は「設定を書いた」という意味です。制限が働くことを確認した、という意味ではありません。

## 4. 現在の設定と境界を検査する

```bash
python3 scripts/set_agent_boundary.py status
python3 scripts/set_agent_boundary.py verify --readable AGENTS.md --blocked-dir ..
```

`verify`は指定した読取り可能なファイルを1バイト読み、`--blocked-dir`内に作る使い捨てファイルが読めないことを検査します。ファイル内容は表示しません。使い捨てファイルは検査後に削除します。境界外の実在する個人ファイルを読む必要はありません。

グラフ限定の設定では`--readable paper_knowledge/ENTRYPOINT.md`を指定します。読取り成功と拒否の両方を確認できた場合だけ`state: probe_passed`を返します。非対応CLI、起動失敗、予想外の読取り成功はすべてエラーになります。LLMの起動や学習は行いません。

この検査は指定した2か所について、新しいCLIサンドボックスの動作を確認するものです。アプリの稼働中タスクや全パスの保証ではありません。外部MCP・コネクターのアクセス権は、それぞれの設定で管理します。

## 元に戻す

```bash
python3 scripts/set_agent_boundary.py restore
```

適用前のファイルを元の内容で復元します。適用後に人間が設定ファイルを変更していた場合は、その編集を消さないよう停止します。復元後も新しいセッションを開始してください。

この仕組みはCodexのプロジェクト設定であり、OS全体のアクセス権を変更するものではありません。人間が別の権限設定へ切り替えれば、その設定が使われます。

仕様の参照先：[OpenAIの権限設定](https://learn.chatgpt.com/docs/permissions)。
