# 機能アップデートの引き継ぎ

ディレクトリの更新作業を別のセッションへ渡す機能です。研究の進行記録とは分離しており、研究状態・実験結果・承認は変更しません。

## 依頼方法

現在のセッション：

```text
今回のディレクトリ更新について、$handoff-maintenance で引き継ぎを作成してください。
変更内容、判断理由、残作業、確認結果、次に読むファイルをまとめ、既存の未コミット変更を区別してください。
```

次のセッション：

```text
ディレクトリ更新の続きを引き継いでください。
まず python3 scripts/maintenance_handoff.py check を実行し、maintenance/HANDOFF.md を読んでください。
保存後の変更を確認し、指定された必要なファイルだけを読んで、現在の依頼範囲で残作業を進めてください。
```

入口は [maintenance/HANDOFF.md](../maintenance/HANDOFF.md) です。初めて保存するまでは、このファイルはありません。

## 記録の役割

| ファイル | 役割 |
|---|---|
| `maintenance/TASK.json` | 編集するメモ。目的、判断、残作業、ファイル、確認結果 |
| `maintenance/HANDOFF.md` | 次の人・Agentが読む要約。最大6,000文字 |
| `maintenance/HANDOFF.json` | 指定ファイルのhashとGit状態。変更検出用の記録 |
| `maintenance/TASK.template.json` | 作業メモのひな型 |

hashは内容が変わると値も変わる識別値です。ソース本文は複製せず、この値で保存後の変更を確認します。

`status`は`in_progress`（途中）、`blocked`（判断・準備待ち）、`complete`（依頼された作業は完了）です。途中なら`next_steps`に次の具体的な作業を残します。メモは英語で記入します。

`scope`は変更検出の対象で最大40ファイル、`read_next`は再開時に先に読む最大8ファイルです。正確な相対パスを指定し、ディレクトリやワイルドカードは使いません。削除済み・作成予定のファイルも指定できます。読込量は1ファイル2 MiB、合計8 MiBまでです。

`checks`にはコマンド、`passed`・`failed`・`not_run`、結果の説明を記入します。未実行は`not_run`です。必要な実行環境は`constraints`へ残します。結果は記入者による報告であり、保存スクリプトがテストを再実行して保証するものではありません。

## 手動操作

初回だけ作業メモを作成します。既存のメモは上書きしません。

```bash
python3 scripts/maintenance_handoff.py init --objective "Describe the directory improvement"
```

`TASK.json`を埋めた後、保存して確認します。

```bash
python3 scripts/maintenance_handoff.py save
python3 scripts/maintenance_handoff.py check
```

`save`は現在の引き継ぎを更新します。履歴を自動蓄積する機能ではありません。別マシンへ渡す場合は、変更したコードと合わせて`TASK.json`と二つの`HANDOFF`ファイルも渡します。コミット・アップロード・別タスクの作成は自動では行いません。

## 再開時の判定

| 表示 | 意味と対応 |
|---|---|
| `current` | 指定ファイル、メモ、Git状態が保存時と一致。現在の依頼を確認して残作業へ進む |
| `stale` | 保存後に変化あり。表示されたファイルとGitの差分を確認し、影響する検証をやり直す |
| `missing` | 未保存。前のセッションで保存するか、現在の依頼から作成する |
| `ERROR` | 形式、パス、サイズ等に問題あり。表示された問題を直す |

`OK`は確認コマンド自体の成功です。続く`status`も確認してください。コミットやブランチ変更も`stale`になります。警告を消すためだけに再保存せず、差を確認してメモと検証結果を更新します。

検出は**指定ファイルの範囲**に限られます。Git状態も補助的に確認しますが、指定外ファイルの内容まで保証しません。データ、成果物、原資料、進行中・終了済み実験、レビュー資料は収集できません。研究状態の引き継ぎには使わないでください。

記録されたコマンドは自動実行しません。過去の承認、無介入モード、アクセス権限も引き継ぎません。常に最新の依頼と現在の権限が優先されます。
