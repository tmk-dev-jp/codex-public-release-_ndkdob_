# 研究質問と新規性を忘れない研究ループ

各工程の冒頭では `research/CONTEXT.md` の **Research Focus** を確認します。
ここには研究質問、今回の目的、実験の役割、新規性の主張、代替説明、
両者を見分ける証拠、反証条件が表示されます。

正本は `research/GOAL.md` と実験の `EXPERIMENT.md` です。Focusを別途編集する
必要はありません。実験完了後も直近の実験から引き継ぎます。文脈の上限で
Focus自体が収まらない場合はエラーにし、黙って削りません。

| 工程 | 確認すること |
|---|---|
| 候補生成 | 研究質問のどの未解決部分に答えるか。既存研究と共有する点、異なる点は何か |
| 新規性監査 | 近い2〜3件の出典と比較。名前や指標値だけの違いになっていないか |
| 計画 | その違いが正しければ何が観測され、どの結果なら棄却されるか |
| 実装・実行前監査 | 変更箇所と対照条件が、その問いと差分を検証する構成になっているか |
| 評価 | 指標が改善したかに加え、問いに答えたか、新規性の主張をどこまで支持したか |
| 記憶・次の方向 | 支持・反証・未検証を残し、次は不足している識別証拠を補うか |

新規性監査の `similar_items` は、各項目に `source`（URLまたは資料ID）、
`shared`（共通点）、`difference`（差分）を持たせます。
`facet_comparison` は `mechanism`、`condition`、`data_regime`、`objective`、
`implementation_change` を比較します。同じ部分は「同じ」と明記します。
空の根拠に `proceed` と書いても、検証とルーターは通しません。
資料が足りない場合は `needs_human` などで不足を残し、出典を作りません。

評価用 `DECISION_FACTS.json` にもFocusが入り、問いや新規性の記述を変えると
既存の評価資料は古いものとして検出されます。新規性記録を変えた場合も
以前の計画監査はそのまま再利用できません。計画や研究質問の変更は、
通常の改訂・監査・人間の判断を経て行います。

評価では `Supported scope` に問いへの答えと支持された差分を、
`Unsupported or missing evidence` に未検証・交絡・反証を記録します。
良い指標値だけでは新規性を確定しません。smoke実験は動作確認の証拠です。

この仕組みは問いと根拠の継続性を支えるもので、新規性そのものを自動証明する
ものではありません。検索は承認範囲内の少数の近接資料に留め、結果が少ない
ことを新規性の根拠にはしません。
